## 1. 기술 스택 및 API 설계

PRD 6번 "기술 스택" 항목이 비어있음. 프론트-백 분리 구조에서 확정 필요:

- **API 스펙**: REST vs GraphQL, 문서화 방식 (Swagger 등)
- **인증 플로우**: 카카오 OAuth에서 프론트가 어디까지 처리하는지
- **LLM 스트리밍**: AI 인터뷰어 응답 전달 방식 (SSE? WebSocket?)
- **배포 환경**: 프론트/백 각각 어디에 배포?

**제안**: Week 1에 API 계약(endpoint, request/response 형태)을 먼저 확정하자.

## 2. AI 인터뷰어 UX 방향 (킬러 피처)

PRD에 "갭 항목별로 질문 → 경험 추출 → 표현 정리"만 적혀있고, 구체적인 UI 형태가 없음.

### 선택지

| 방식                                    | 구현 난이도                       | 사용자 경험        |
| --------------------------------------- | --------------------------------- | ------------------ |
| 채팅형                                  | 높음 (스트리밍, 히스토리, 스크롤) | 자연스러움         |
| 단계별 폼                               | 낮음                              | "인터뷰" 느낌 약함 |
| 하이브리드 (AI 질문 카드 + 텍스트 답변) | 중간                              | MVP에 현실적       |

**제안**: 디자이너 화면 스케치 전에 방향을 합의해야 헛수고를 방지할 수 있음.

## 3. JD 입력 방식 — Must Have 승격 필요

현재 상태:

- Must Have: 공고 URL 분석
- Should Have: JD 직접 입력

**문제**: 원티드/사람인/잡코리아 등 채용 사이트는 SPA가 많아 URL fetch로 JD 텍스트 추출이 어려움. 크롤링 실패율이 높을 것으로 예상.

**제안**: JD 직접 붙여넣기를 **Must Have로 승격**, URL 분석은 편의 기능으로.

- 베타 30명이 URL 넣었는데 "분석할 수 없는 공고입니다"가 뜨면 첫인상이 끝남
- 텍스트 붙여넣기가 메인, URL 분석이 부가 기능

## 4. 이력서 편집 화면 범위

PRD: "AI 제안을 보고 본인이 직접 다듬는 편집 화면"

### 수준별 개발량

| 수준    | 설명                                  | 개발 기간           |
| ------- | ------------------------------------- | ------------------- |
| Level 1 | AI 제안 문구 보여주기 + 복사 버튼     | 1-2일               |
| Level 2 | 이력서 텍스트 직접 편집 (간단 에디터) | 3-5일               |
| Level 3 | PDF 인라인 편집                       | 2-3주+ (MVP 불가능) |

**제안**: MVP는 Level 1 (AI 제안 문구 복사). 직접 편집은 v2.

- PM한테 "편집 화면"이 정확히 뭘 의미하는지 확인 필요

---

## 5. 이력서 재사용 기능 (버전 관리 최소 버전)

PRD 맨 마지막 PM 고민: "버전별, 공고별 이력서 관리 기능이 있어야 LLM과의 차별성, 리텐션 효과"

**문제**: 이력서 재사용이 안 되면 한 번 쓰고 끝나는 서비스 → 재방문 없음 → 피드백 수집 불가

**제안**: 전체 버전 관리는 Could Have로 유지하되, **"이전에 등록한 이력서를 다시 선택해서 새 공고에 사용"** 기능은 MVP에 포함.

- 기술적으로 크지 않음: 유저별 이력서 목록 저장 + 선택 UI

## 6. 일정 현실성

- 전체 기간: 6-7주
- 디자인/기획: ~2주
- QA/배포: ~1주
- **순수 개발 기간: 3-4주**

Must Have 기능만 해도 화면 7개+:

1. 로그인
2. 이력서 등록 (PDF 업로드)
3. 공고 입력 (URL + 텍스트)
4. 갭 분석 결과
5. AI 인터뷰
6. 결과/제안 (AI 제안 문구 확인)
7. 이력서 목록 (재사용)

**제안**:

- Week 1-2: 핵심 플로우 (이력서 등록 → 공고 입력 → 갭 분석) 먼저 완성
- Week 3-4: AI 인터뷰어 붙이기
- 전체를 동시에 시작하면 아무것도 완성 못 함

## 8. 디자이너 협업 방식

**합의된 방향**: 와이어프레임 기반으로 먼저 개발 시작

### 디자이너에게 요청할 것

- **Week 1**: 핵심 화면 와이어프레임 먼저 전달
- **Week 2-3**: 비주얼 디테일 (컬러, 아이콘, 간격 미세 조정)
- Tailwind 기본 간격 체계(4px 배수: 4, 8, 12, 16, 20, 24...)로 디자인 요청
- 공통 컴포넌트 5-7개만 먼저 정의 (버튼, 입력필드, 카드, 모달, 헤더, 토스트)
- 완벽한 디자인 시스템은 6-7주 프로젝트에서 오버헤드

## 9. LLM API 비용

PRD 6번에 PM이 직접 "이거 비용?" 이라고 적어둔 항목.

### 예상 호출량

- 갭 분석 1회 + AI 인터뷰 5-6턴 + 표현 정리 = **유저 1명 × 공고 1개당 최소 3-4회 LLM 호출**
- 베타 30명 × 공고 3개씩 = **약 300-360회 API 호출**
- GPT-4 기준 1회 호출당 input+output 약 2,000-4,000 토큰 → 전체 약 $5-20+ (모델/사용량에 따라 변동)

### 회의에서 확인할 것

- 무료 베타 기간 LLM 비용을 누가 부담하는지 (팀 공동? SWYP 지원?)
- 모델 선택: GPT-4 vs GPT-4o-mini vs Claude Haiku 등 — 비용과 품질 트레이드오프
- 유저당 일일 사용 제한을 둘 건지 (무제한이면 비용 폭발 가능)

**제안**: 개발 초기에는 저렴한 모델(GPT-4o-mini 등)로 PoC 하고, 품질이 부족하면 핵심 단계만 상위 모델로 올리는 전략.

## 회의 때 꺼내는 순서 추천

1. **일정 현실성** (6번) — 전체 톤 세팅. "3-4주밖에 없다"를 공유
2. **JD 입력 방식** (3번) — 빠른 합의 가능, Must Have 조정
3. **AI 인터뷰어 UX** (2번) — 킬러 피처 방향성 합의
4. **이력서 편집 범위** (4번) — PM 기대치 조정
5. **이력서 재사용** (5번) — MVP 범위 조정
6. **디자이너 협업** (8번) — 병렬 진행 합의
7. **기술 스택/체크리스트** (1번, 7번) — 백엔드와 상세 논의
8. **LLM 비용** (9번) — 베타 비용 부담, 모델 선택, 사용 제한
