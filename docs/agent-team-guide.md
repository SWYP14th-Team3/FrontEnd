## 1. 에이전트 설정 위치: 글로벌 vs 프로젝트

에이전트는 `.md` 파일로 정의하며, 위치에 따라 적용 범위가 달라진다.

```
~/.claude/agents/          ← 글로벌 (모든 프로젝트에서 사용 가능)
.claude/agents/            ← 프로젝트 (이 프로젝트에서만 사용 가능)
```

**이름이 겹치면 프로젝트 에이전트가 글로벌을 덮어쓴다.**

### 글로벌 에이전트 (`~/.claude/agents/`)

어떤 프로젝트에서든 동작해야 하므로 **프로젝트 특정 규칙을 하드코딩하지 않는다.**

```markdown
# 글로벌 reviewer.md 예시

- CLAUDE.md와 .claude/rules/가 있으면 읽고 따른다
- git diff 기반으로 변경된 파일만 리뷰한다
- 린트/빌드 명령은 package.json에서 찾아서 실행한다
```

적합한 에이전트:

| 에이전트    | 역할                | 왜 글로벌?                |
| ----------- | ------------------- | ------------------------- |
| reviewer    | diff 기반 코드 리뷰 | 어떤 언어/프로젝트든 가능 |
| planner     | 작업 분해/설계      | 프로젝트 무관한 스킬      |
| test-writer | 테스트 코드 생성    | 프레임워크 자동 감지      |
| doc-writer  | 문서 생성           | 범용                      |

### 프로젝트 에이전트 (`.claude/agents/`)

도메인, 기술 스택, 팀 컨벤션에 맞춘 맞춤형 에이전트.

```markdown
# 프로젝트 frontend.md 예시

- .claude/rules/의 규칙을 따른다
- cn() + cva() 패턴 사용
- Next.js 16 App Router + TypeScript
- ResuFit 도메인 용어 사용
```

### 관계 정리

```
글로벌 (범용 뼈대)                  프로젝트 (맞춤 살)
┌──────────────────────┐           ┌──────────────────────┐
│ "CLAUDE.md 있으면 읽어"│    →     │ "Next.js 16 써"       │
│ "규칙 파일 있으면 따라" │    →     │ "cn() + cva() 패턴"   │
│ "빌드 명령 자동 감지"   │    →     │ "pnpm build 실행"     │
│ "린트 도구 자동 감지"   │    →     │ ".claude/rules/ 따라" │
└──────────────────────┘           └──────────────────────┘
```

## 2. 설정 파일 스코프

에이전트뿐 아니라 훅, 권한 등의 설정 파일도 위치에 따라 범위가 다르다.

| 파일                          | 범위          | Git 커밋    | 용도               |
| ----------------------------- | ------------- | ----------- | ------------------ |
| `~/.claude/settings.json`     | 모든 프로젝트 | N/A         | 개인 글로벌 환경   |
| `.claude/settings.json`       | 이 프로젝트   | O (팀 공유) | 팀 규칙/훅         |
| `.claude/settings.local.json` | 이 프로젝트   | X (나만)    | 개인 프로젝트 설정 |

설정은 `글로벌 → 프로젝트 → 로컬` 순서로 로드되며, 뒤의 것이 앞을 덮어쓴다.

### 어디에 넣어야 하나?

| 설정               | 위치                          | 이유                    |
| ------------------ | ----------------------------- | ----------------------- |
| tmux 훅/권한       | `~/.claude/settings.json`     | 개인 환경 설정          |
| 팀 공유 훅         | `.claude/settings.json`       | 팀원 모두 적용          |
| 개인 프로젝트 설정 | `.claude/settings.local.json` | 다른 프로젝트 영향 없음 |

## 3. 에이전트 팀 운용 방식: TeamCreate vs tmux

에이전트를 팀으로 운용하는 방법은 두 가지가 있다.

### TeamCreate (내장 기능)

Claude Code에 내장된 에이전트 팀 기능. `TeamCreate` 도구로 팀을 만들고, `SendMessage`로 팀원끼리 직접 통신한다.

```
TeamCreate("resufit-team")
    │
    ├── 팀 리드 (메인 세션) — 태스크 생성, 조율
    │
    ├── Agent(name="frontend-1", team_name="resufit-team")
    │   └── 태스크 리스트에서 작업 가져가서 구현
    │       SendMessage로 reviewer에게 "리뷰 부탁"
    │
    └── Agent(name="reviewer", team_name="resufit-team")
        └── 리뷰 요청 받으면 검증
            SendMessage로 frontend에게 "여기 수정해"
```

**워크플로우:**

1. `TeamCreate`로 팀 생성 (팀 = 공유 태스크 리스트)
2. `Agent` 도구로 팀원 스폰 (각 팀원이 팀에 합류)
3. 태스크 생성/배분
4. 팀원들이 `SendMessage`로 서로 직접 대화하며 협업
5. 작업 완료 후 `TeamDelete`로 정리

### tmux (외부 도구)

각 에이전트를 독립된 `claude` 프로세스로 tmux pane에 실행. 파일 기반으로 통신한다.

```
┌─ tmux pane 0 ──────┐  ┌─ tmux pane 1 ──────┐  ┌─ tmux pane 2 ──────┐
│ claude (planner)    │  │ claude (frontend)   │  │ claude (reviewer)  │
│                     │  │                     │  │                    │
│ 독립 프로세스       │  │ 독립 프로세스       │  │ 독립 프로세스      │
│ 독립 컨텍스트       │  │ 독립 컨텍스트       │  │ 독립 컨텍스트      │
│ 독립 모델           │  │ 독립 모델           │  │ 독립 모델          │
└─────────────────────┘  └─────────────────────┘  └─────────────────────┘
         │  파일/태스크 보드로 통신  │                        │
         └──────────────────────────┴────────────────────────┘
```

**핵심 메커니즘:**

- 오케스트레이터가 `tmux send-keys -t pane1 "프롬프트" Enter`로 작업 지시
- `tmux capture-pane -t pane1 -p`로 결과 읽어옴
- 공유 파일(태스크 보드)로 상태 동기화

### 비교

|                   | TeamCreate                         | tmux                         |
| ----------------- | ---------------------------------- | ---------------------------- |
| **컨텍스트**      | 공유 (하나의 프로세스 안에서 분산) | 각자 독립 (풀 컨텍스트)      |
| **병렬성**        | 논리적 병렬                        | 물리적 병렬 (진짜 동시 실행) |
| **통신**          | `SendMessage` (내장, 안정적)       | 파일 기반 (수동 구성 필요)   |
| **세팅 난이도**   | 쉬움                               | 복잡함                       |
| **컨텍스트 소진** | 팀원 많으면 빠르게 소진            | 각자 독립이라 문제 없음      |
| **적합한 규모**   | 작은~중간 작업                     | 대규모 작업                  |

### 언제 무엇을 쓰나?

- **TeamCreate**: 하나의 기능 구현, 컴포넌트 몇 개 만들기 같은 중소 규모 작업
- **tmux**: 여러 페이지를 동시에 구현하거나, 대규모 리팩토링처럼 각 에이전트가 오래 작업해야 할 때

## 4. 서브에이전트 vs 에이전트 팀

에이전트를 호출하는 방식에도 차이가 있다.

### 서브에이전트 (`Agent` 도구 단독 사용)

```
메인 에이전트
├── Agent("이거 해줘") → 결과 보고
├── Agent("저거 해줘") → 결과 보고
└── 메인이 결과 종합
```

- 결과만 메인에게 **일방향 보고**
- 서브에이전트끼리는 서로 모름
- 메인이 모든 조율을 담당

### 에이전트 팀 (`TeamCreate` + `SendMessage`)

```
팀 리드
├── frontend-1 ←→ reviewer    (직접 대화)
├── frontend-2 ←→ reviewer    (직접 대화)
└── 공유 태스크 리스트           (모두 접근 가능)
```

- 팀원끼리 `SendMessage`로 **직접 통신**
- 공유 태스크 리스트에서 **자율적으로 작업을 가져감**
- 팀 리드는 조율만, 팀원들이 알아서 협업

|               | 서브에이전트         | 에이전트 팀                   |
| ------------- | -------------------- | ----------------------------- |
| **통신**      | 결과만 메인에게 보고 | 팀원끼리 직접 대화            |
| **작업 관리** | 메인이 일방적 지시   | 공유 태스크 리스트            |
| **자율성**    | 시킨 것만 수행       | 스스로 태스크 확인하고 가져감 |
| **구조**      | 트리 (부모 → 자식)   | 팀 (리드 + 동료들)            |

## 5. 현재 프로젝트의 에이전트 구성

`.claude/agents/`에 3개의 프로젝트 에이전트가 정의되어 있다.

| 에이전트   | 모델   | 역할                             | 코드 작성     |
| ---------- | ------ | -------------------------------- | ------------- |
| `planner`  | opus   | 작업 분해/조율, 파일 소유권 지정 | X (조율 전용) |
| `frontend` | sonnet | 페이지/컴포넌트/스타일링 구현    | O             |
| `reviewer` | opus   | 코드 검증, 체크리스트 기반 리뷰  | X (검증 전용) |

### 팀 워크플로우

```
사용자 요청
    │
    ▼
planner (opus)
    │ 작업 분해 + 파일 소유권 배분
    ▼
frontend (sonnet) × N
    │ 구현
    ▼
reviewer (opus)
    │ 검증 (PASS / FAIL + 수정사항)
    ▼
  완료 or frontend에게 수정 요청
```

## 6. 실제 사용법

### TeamCreate 방식

```
사용자: "이력서 업로드 페이지 만들어줘"

→ Claude가 TeamCreate로 팀 구성
→ planner가 작업 분해
→ frontend 에이전트들이 구현
→ reviewer가 검증
→ 완료
```

### tmux 방식

```bash
# 1. tmux 세션 생성
tmux new-session -s resufit-team -d

# 2. 각 pane에서 claude 실행
tmux send-keys -t resufit-team "claude --agent planner" Enter
tmux split-window -t resufit-team
tmux send-keys -t resufit-team "claude --agent frontend" Enter
tmux split-window -t resufit-team
tmux send-keys -t resufit-team "claude --agent reviewer" Enter

# 3. 세션 접속
tmux attach -t resufit-team
```

통신은 공유 파일(태스크 보드 등)을 통해 수동으로 구성해야 한다.
