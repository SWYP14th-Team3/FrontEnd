## 🛠️ 기술 스택 및 의사결정

### 1. 왜 Next.js인가?

- **SSR / SSG 기본 지원**: SEO와 초기 로딩 성능에 유리
- **App Router**: 레이아웃, 로딩, 에러 처리를 파일 기반으로 간결하게 관리
- **React 19 + React Compiler**: 최신 React 기능과 자동 최적화를 바로 사용 가능
- **Vercel 배포 최적화**: 별도 설정 없이 바로 배포 가능
- **풀스택 가능**: API Routes로 간단한 백엔드 로직도 처리 가능

### 2. 패키지 매니저 — pnpm

| 비교        | npm  | yarn | pnpm | Bun       |
| ----------- | ---- | ---- | ---- | --------- |
| 속도        | 보통 | 보통 | 빠름 | 가장 빠름 |
| 디스크 효율 | 낮음 | 보통 | 높음 | 높음      |
| 호환성      | 최고 | 좋음 | 좋음 | 제한적    |

> **선택 근거**: 2026년 기준 신규 프로젝트 채택률 1위. 속도·안정성·호환성 밸런스가 가장 좋음. Bun은 빠르지만 런타임 종속 이슈가 있어 제외.

### 3. Next.js 설정

| 옵션           | 선택 | 이유                                                     |
| -------------- | ---- | -------------------------------------------------------- |
| TypeScript     | ✅   | 타입 안정성, 협업 시 코드 가독성                         |
| App Router     | ✅   | Next.js 권장 라우팅 방식                                 |
| src/ 디렉토리  | ✅   | 루트와 소스코드 분리로 프로젝트 구조 깔끔                |
| Tailwind CSS   | ✅   | 유틸리티 기반 스타일링, 빠른 UI 개발                     |
| React Compiler | ✅   | v1.0 정식 출시(2025.10), useMemo/useCallback 자동 최적화 |
| Turbopack      | ✅   | 개발 서버 빌드 속도 향상                                 |

## ⚙️ 코드 품질 도구

### ESLint — 코드 린터

코드에서 잠재적 오류나 안티패턴을 **정적으로 분석**합니다.
예: 사용하지 않는 변수, 잘못된 import, React Hook 규칙 위반 등을 감지.

- `eslint-config-next` (core-web-vitals + typescript) 기본 포함
- `eslint-config-prettier` → Prettier와 규칙 충돌 방지

### Prettier — 코드 포매터

코드 스타일(들여쓰기, 따옴표, 줄바꿈 등)을 **자동으로 통일**합니다.
누가 작성하든 동일한 코드 스타일을 유지할 수 있음.

| 옵션                        | 값   | 이유                                                   |
| --------------------------- | ---- | ------------------------------------------------------ |
| printWidth                  | 120  | 80은 실무에서 너무 좁음, 와이드 모니터 기준 120이 적합 |
| singleQuote                 | true | 가장 보편적인 설정                                     |
| tabWidth                    | 2    | 들여쓰기 2칸                                           |
| trailingComma               | all  | 마지막 항목 뒤에도 쉼표 (Git diff 깔끔)                |
| endOfLine                   | lf   | Win/Mac 줄바꿈 통일                                    |
| prettier-plugin-tailwindcss | ✅   | Tailwind 클래스 자동 정렬                              |

### Husky — Git Hook 관리

Git 커밋, 푸시 등의 **이벤트에 자동으로 스크립트를 실행**합니다.
현재 `pre-commit` 훅에서 lint-staged를 실행하도록 설정.

### lint-staged — 스테이징 파일 검사

**커밋하려는 파일에만** 린트/포매팅을 실행합니다.
전체 프로젝트를 검사하지 않아 빠르고 효율적.

| 파일 타입                 | 실행 작업                          |
| ------------------------- | ---------------------------------- |
| `*.ts`, `*.tsx`           | ESLint 자동 수정 + Prettier 포매팅 |
| `*.json`, `*.css`, `*.md` | Prettier 포매팅                    |

> **흐름**: `git commit` → Husky(pre-commit) → lint-staged → 린트/포매팅 통과 시 커밋 완료, 실패 시 커밋 차단

## 📦 유틸리티 라이브러리

| 라이브러리                       | 용도                                        |
| -------------------------------- | ------------------------------------------- |
| `class-variance-authority (cva)` | 컴포넌트 variants 정의                      |
| `clsx`                           | 조건부 className 조합                       |
| `tailwind-merge`                 | Tailwind 클래스 충돌 시 마지막 값 우선 적용 |

`cn` 유틸 함수 (`src/lib/utils.ts`): `clsx` + `tailwind-merge` 조합

```ts
import { type ClassValue, clsx } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

> **선택 근거**: Tailwind 기반 컴포넌트 개발 시 사실상 필수 조합. shadcn/ui에서도 동일한 패턴 사용.

## 🌿 브랜치 전략

**뤼이도**(프로젝트 관리 도구)에서 티켓 생성 시 브랜치명을 복사하여 사용합니다.

### 브랜치 네이밍

```
{접두사}/{뤼이도 티켓 ID}
```

| 접두사      | 용도               | 예시                                     |
| ----------- | ------------------ | ---------------------------------------- |
| `feat/`     | 기능 구현          | `feat/13-21-FE-로그인-페이지-구현`       |
| `fix/`      | 버그 수정          | `fix/14-22-FE-헤더-렌더링-오류-수정`     |
| `chore/`    | 환경설정, 리팩토링 | `chore/13-21-FE-레포-프로젝트-초기-세팅` |
| `refactor/` | 코드 개선          | `refactor/15-23-FE-API-로직-분리`        |

### 브랜치 흐름

```
main ← feat/티켓ID (PR 병합)
```
